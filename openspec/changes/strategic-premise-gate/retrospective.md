## Supported agent lesson

- A pre-implementation strategic-premise gate can materially improve architecture selection: challenger mean strategic fit improved by `0.133`, and mean unjustified construction fell from `1.600` to `0.467`.
- Improvement in means is not sufficient for promotion. A useful gate must consistently stop after discovering the narrow repository-owned gap; the challenger often named existing capabilities correctly and still added parallel ingestion, audit, action, catalog, or dashboard surfaces.
- The construction-favored holdout is essential. It showed that the challenger could authorize narrow custom construction without a systematic “reuse everything” refusal, isolating the defect to incomplete boundary minimization rather than blanket blocking.
- Conservative count aggregation exposed real failures that scalar prose quality could hide. Keep zero-tolerance construction/blocking metrics protected and prerequisite to primary improvement.

## Invalidated assumptions

- “Existing-capability reconnaissance plus a build-versus-integrate table will reliably prevent redundant construction” was invalidated. All three protected integration-favored challenger responses retained at least one unjustified owned component.
- “A capability spike or managed-service choice is enough to prove a narrow boundary” was invalidated. Responses used spikes and Sentry integration while still duplicating incident/action/evidence/catalog persistence.
- “Schema-constrained grader JSON guarantees a completed grade” was invalidated by the schema-valid `Pending…`/confidence-zero record.
- “Read-only snapshots isolate evaluation identity and protected files” was too strong. Read-only prevented writes, but shared Git/worktree metadata and shared-host paths remained discoverable.

## Evaluation gaps and routed suggestions

- Any revised strategic-premise skill should be a new challenger. Test explicit subtraction: after selecting a design, require a component-by-component proof that each new service, queue, table set, dashboard, adapter, and coordinator fills a demonstrated gap not covered by existing datastore, evaluator, evidence, or rollback paths.
- Add protected cases where integration is selected but repository evidence/audit should be extended rather than duplicated, and cases where vendor integration is inappropriate so the skill cannot learn “managed service” as the answer.
- Add semantic grader validation: reject final records containing pending/in-progress placeholders, require nonzero completion confidence or evidence-backed rationales, and predeclare the replacement rule before grading.
- Run candidates in isolated filesystem/mount namespaces with only the source snapshot and ordinary prompt visible. Export source archives without shared Git worktree metadata for stronger candidate blinding.
- Record normalization/composition recipes for every bundle/policy hash. A digest without a reproducible recipe is provenance, not independent integrity proof.
- Preserve the current repository strategic-premise policy as owner-directed policy if desired, but do not call this challenger empirically promoted. Any code/policy revision, promotion claim, or tag requires a new accepted agent-evolution change and independently frozen evaluation.
