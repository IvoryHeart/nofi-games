## Component change

Add challenger skill `validate-strategic-premise` and require its gate for consequential architecture changes. The exact challenger also adds a regression fixture based on `durable-agent-runtime`; it does not change product, gameplay, release, or agent-promotion policy.

## Expected quality effect and mechanism

Compared with the champion at `c6b891d`, the challenger will more reliably identify existing platform and harness capabilities, distinguish control plane from harness and model layers, compare reuse with construction, and stop implementation when the proposed abstraction exceeds its evidence. It acts before proposal-derived tests can validate a strategically incorrect premise.

## Protected metrics

- No reduction in satisfying explicit user outcomes and constraints.
- No invented capability claims or reliance on non-authoritative sources for current product behavior.
- No increase in blocking ordinary localized implementation that does not trigger the gate.
- No loss of reversibility, evidence provenance, security, or independent promotion requirements.
- Gate output remains concise enough to be read before implementation and contains every declared field.
- Existing-capability reuse must not become a rule against custom construction when evidence shows an actual gap.

## Disconfirming result

Reject the challenger if repeated blinded architecture fixtures show no material reduction in duplicated systems, if it incorrectly blocks justified construction, if it collapses distinct layers into a lowest-common-denominator abstraction, or if it can only pass when given the expected architecture answer.
